# Purpose

Architecture governance and directives for AI agents in this repository.

## Ownership

Project Maintainers and AI Engineering Agents.

## Local Contracts

- **Universal English Documentation Default Mandate & Language Governance (`validate_documentation_language`)**: Across `@francogp/auditor` and all consumer host applications governed by it, all documentation, DOX indices, and learning proposals (`learning_proposal.md` generated by `learn-with-docs`) depend strictly on the language configured in `config.documentation?.language`. Whenever in doubt, or if not explicitly declared in `.auditor/audit.config.ts`, the default language is STRICTLY AND UNCONDITIONALLY English (`'en'`). This is a mandatory universal default across all projects. Natural language across repository markdown, documentation, manuals, blueprints, and AI skills under `.agents/skills/**` is governed strictly by this setting (optionally `'es'`). The engine extracts human prose while strictly stripping technical code blocks, inline code, markdown links/URLs, and YAML frontmatter. Any non-authorized language triggers blocking violations (`severity: 'error'`), with path-based exemptions configured via `config.documentation.languageExemptions`. Sub-auditors must never skip or hesitate due to unconfigured language; `'en'` applies automatically by default everywhere.
- **Prohibition on Modifying or Disabling Configurations Without Prior Programmer Consultation**: Developers and AI agents are strictly prohibited from disabling, turning off, altering, or modifying auditor configurations (`.auditor/audit.config.ts`, `vite.config.ts`, `.stylelintrc.json`, `.fallowrc.json`) when encountering errors or warnings without consulting and obtaining explicit prior authorization from the human programmer. When requesting authorization, the agent must provide a comprehensive technical explanation detailing why the modification is necessary, explicitly justifying the trade-offs, pros, and cons.
- **Absolute Prohibition on Backward-Compatible Code & Loud Failure Mandate**: Writing backward-compatible shims, deprecated alias suites, legacy fallback wrappers, or dual-execution adapter code across this repository is STRICTLY PROHIBITED. The architecture prioritizes clean, uncompromised modern standards over legacy tolerance. Outdated consumers, legacy configurations, and unmigrated calls MUST fail loudly with immediate, explicit, and blocking errors (`throw new Error(...)` or exit code 1) forcing immediate upgrades to canonical standards. Maintaining duplicate suites or runtime compatibility bridges that introduce bloat, duplicate findings, or maintenance hazards is completely eradicated.
- **Absolute Prohibition on Suppressing, Silencing, Nullifying, or Bypassing Audit Rules & Zero-Tolerance Fake Pass Mandate**: When auditing a repository or running linters/auditors, AI agents and developers are STRICTLY AND CATEGORICALLY PROHIBITED from suppressing, silencing, disabling, or nullifying auditor rules, stylelint rules, ESLint rules, or any static analysis checks (e.g., setting `"rule": null`, `"rule": "off"`, `"rule": 0`, creating dummy override configs that neuter checks, or passing arbitrary skip flags) to make an audit pass or hide findings. If the number of errors or warnings is massive (even thousands of errors), THEY ARE REAL ARCHITECTURAL OR HYGIENE DEFECTS THAT MUST BE LEGITIMATELY RESOLVED IN THE SOURCE CODE OR FIXED WITH CANONICAL TOOLS (`auditor fix`). Modernizing host configurations means elevating the codebase to meet strict modern standards and exposing defects that were previously hidden, NEVER degrading, diluting, or castrating the auditor's rules to fit legacy code. Silencing rules to achieve a fake clean pass is considered a critical architectural violation and gross misconduct.
- **AI Agent Chat Communication & Interactive Language Mandate**: The AI assistant / agent MUST strictly consult `.auditor/audit.config.ts` and communicate, converse, respond, and chat with the user in Spanish (`'es'`). Furthermore, all conversational interactions and AI agent brain artifacts (plans, task lists, walkthroughs, brain reports, markdown proposals generated in `<appDataDir>/brain/<conversation-id>`) MUST be written in Spanish (`'es'`). This conversational and artifact language is explicitly separate and distinct from the repository file writing and documentation language (`config.documentation.language`), which strictly governs code comments, commit messages, documentation, and codebase repository files. The AI agent must dynamically consult these configurations and never confuse or conflate the chat and artifact language with the file writing language.
- **Absolute Prohibition on Unrequested Destructive Git Commands**: AI agents are STRICTLY AND CATEGORICALLY PROHIBITED from executing destructive Git commands (`git reset --hard`, `git checkout --`, `git clean`, `git restore`, `git push --force`) that discard or overwrite working tree changes or commit history without explicit prior authorization from the human programmer.
- **Mandatory Official Tools Priority & Prohibition on Premature Ad-Hoc Scripts**: Developers and AI agents MUST ALWAYS prioritize and use the official CLI tools provided by the framework and package scripts (`npm run auditor:findings`, `npm run auditor:rules`, `npm run auditor:by-rule`, `npm run auditor:by-file`, `npm run auditor:dupes`, `npm run auditor:magic`, `npm run auditor:motion`, `npm run auditor:o1`, `npm run auditor:dependencies`, `npm run auditor:version`, `auditor guide <ruleId>`, `vp check`) before attempting manual inspection or writing code. Reinventing the wheel by creating scratch scripts or ad-hoc `node -e` one-liners for tasks already covered by official tools is STRICTLY PROHIBITED. Creating temporary scripts in `scratch/` is permitted ONLY as an exceptional last resort when no official tool exists for the specific diagnostic or verification task. When invoking npm scripts with flags or subcommands, always use `--` (e.g. `npm run auditor:motion -- --help`, `npm run auditor -- guide <ruleId>`) or invoke the installed binary directly, NEVER invoke `npx`.
- **Universal Architecture Governance & Mandatory Work Planning Alignment Mandate (`/architecture`)**: The `/architecture` governance framework governs all design, structure, runtime behavior, and refactoring across this repository and MUST remain continuously active and strictly enforced. Whenever creating, proposing, or executing any work plan, technical design, refactoring roadmap, or task breakdown (e.g. `/plan`, `/brainstorming`, brain task plans), the proposed work MUST strictly align with and satisfy `/architecture` and its complete contents: the 6 Mandatory Design Pillars (`/domain-type-first`, `/clean-code`, `/dox-navigator`, `/ponytail`, `/auditor`, `/fallow`), the Primary Debugging Guide (`/systematic-debugging` - RED-GREEN First Mandate), decoupled layering, Node.js 26+ native standard library mandate, dynamic SSoT configuration, and official framework tools priority. Deviating from `/architecture` or executing plans that bypass its pillars is strictly prohibited.
- **Dependency Immutability Mandate & Categorical Prohibition on Mutating `node_modules/` (`Dependency Immutability Mandate`)**: Developers and AI agents are STRICTLY AND CATEGORICALLY PROHIBITED from modifying, editing, patching, or writing files inside `node_modules/` under ANY circumstances. Inspecting or reading dependency source code and type definitions is permitted, but packages installed via package managers are immutable runtime artifacts. Copying, transferring, or pasting build artifacts (`dist/`), packages, or files directly into another project's `node_modules/` to test changes is STRICTLY AND CATEGORICALLY PROHIBITED. If a bug or false positive is suspected in `@francogp/auditor` or any installed dependency, the AI agent MUST HALT and report the issue to the human programmer to fix it in the upstream source repository rather than hot-patching `node_modules/`. All cross-project verification MUST execute non-destructively through the canonical remote CLI flag (`project=<path>`) from the auditor workspace or by upgrading via the canonical package update tool (`npm run auditor:update`), NEVER by mutating `node_modules/`. Mutating `node_modules/` introduces untracked volatile state that is immediately destroyed on the next `npm install`, masks upstream architectural debt, and constitutes a critical operational violation.
- **PreToolUse Hook Invariance Mandate & Absolute Prohibition on PreToolUse Bypass Workarounds (`PreToolUse Hook Invariance Mandate`)**: AI agents and developers are STRICTLY AND CATEGORICALLY PROHIBITED from bypassing, evading, silencing, or working around PreToolUse hooks (such as `prevent_destructive_git.js`) through proxy scripts, sub-processes, child scripts in `scratch/`, brain directories, temporary files, eval commands, or indirect shell invocations. If a hook denies access or aborts an operation on a governed satellite configuration file (`vite.config.ts`, `tsconfig.json`, `.fallowrc.json`, `.stylelintrc.json`), THE ACTION IS INTENTIONALLY AND LAWFULLY FORBIDDEN BY ARCHITECTURAL POLICY. For Vite plugins specifically, `vite.config.ts` delegates plugins to `vite.plugins.ts` (100% developer/AI-owned and directly editable); running `npm run auditor:fix` automatically migrates plugins and resolves TypeScript recursion issues (`TS2321`). Any attempt to craft scripts or execute commands specifically designed to conceal target file paths from safety hook matchers is considered a critical security violation, gross architectural misconduct, and immediate grounds for operational revocation.
